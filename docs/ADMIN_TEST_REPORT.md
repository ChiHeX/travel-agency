## 四个主流程验收安排（PRD §63）

| 流程 | 验收步骤与预期 | 协同角色 | 实际执行状态 |
|---|---|---|---|
| 游客报名 | 建线路／行程／团期并分配导游 → 发布 → USER 报名 → 沙箱支付 → STAFF 核实确认；订单、名额和消息一致 | E 协调，B 交易，C 资源，D 用户端 | 未执行：需运行环境和支付沙箱联合验收 |
| 导游执行 | GUIDE 仅查看本人团期及脱敏名单 → 开始 → 完成；他人团期访问失败 | E 协调，C 资源，B 状态流转 | 未执行：需真实团期与多账号浏览器验收 |
| 评价 | USER 对已完成订单评价 → STAFF 查看／隐藏 → 公开页面同步；重复或越权评价失败 | E 协调，B 资格校验，D 用户端 | 未执行：需完整已完成订单链路 |
| 退款 | USER 申请 → STAFF 填意见 → 同意／拒绝；待确认时只能安全重试且不重复出款 | E 协调，B 交易，D 用户端 | 未执行：需支付沙箱及异常结果复核 |

执行时补充：环境／构建提交、测试账号类型（不写密码）、执行人、执行时间、订单或退款单号、
实际结果、证据和关联缺陷。发现问题记录复现步骤，修复后由交叉测试人员复测；未执行项不得改为通过。
