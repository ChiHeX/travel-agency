# PR #9 回归记录

审查基线：PR #9 的 `7a08d40`，叠加本分支已有的认证修复。2026-09-18 核对时，该 PR 仍处于未合并状态。

## 已复现并修复

- 导游创建接口没有创建登录账号、角色关系，且返回 200。现按冻结契约在事务内创建账号和导游，返回 201、Location；重复账号返回 409。
- 工作人员可创建或停用导游账号。现将这两个操作限制为 ADMIN，工作人员仍可维护基础资料。
- 导游更新直接接收实体，允许改绑 userId 和修改状态；同时正常更新会丢失响应 username，无法清空简介，不存在的 ID 也返回成功。现使用专用 DTO 和显式字段更新，保留账号关联，正确返回 404。
- 停用导游只改变资料状态，登录账号仍有效。现同步更新账号状态，旧令牌和登录均被拒绝，重新启用也同步处理。
- 编辑已发布攻略会默认为 DRAFT，可空字段无法清空。现内容更新保留发布状态、作者和发布时间，并支持清空可编辑字段。
- 攻略写入请求接受契约外 status，且标题最短长度和正文最长长度没有校验。现状态仅通过专用端点修改，并补齐长度校验。
- 发起支付未校验必填的 Idempotency-Key。现缺失返回 400，长度不符返回 422。

按照 API 全局规则启用未知 JSON 字段拒绝，契约外字段返回 400。导游和攻略写操作归入服务层；攻略发布、编辑和删除在事务内锁定同一记录，避免状态检查与实际删除之间发生竞态。

## 范围限制

这不是整站验收。支付部分仅修复请求头校验，现有服务尚未按支付幂等键记录并重放完整结果，现有支付适配器也不等于支付宝官方沙箱链路；本次未发起真实支付。数据库并发锁的实现已经检查，但本次未进行并发压力测试。后台导游新增页面仍为既有占位入口，本次验证的是后端接口，不代表页面已完成联调。

## 集成能力声明（尚未达到契约描述的能力）

以下三项属于**当前实现能力的边界**，不是待回归的缺陷。文字在此集中声明，避免后续审查反复把它们当成新发现的偏差，也避免实现被误认为已经具备下列能力。

- **支付幂等尚未落到结果重放。** 契约要求 `Idempotency-Key` 参与支付幂等。现状是：请求头为必填（缺失 400、长度不符 422），第二次调用会被拒绝，但服务端**没有**按该键把首次结果持久化并原样重放。也就是说，重试语义目前是「拒绝重复」而不是「返回同一结果」。
- **支付链路是 HMAC 适配点，不是支付宝官方 SDK。** 回调验签走的是自建 HMAC 校验，并未接入支付宝官方沙箱的签名验签链路。真机联调前，回调侧不能视为已验证。
- **退款中间态不可观测。** `processRefund` 在同一个事务内连续写入 `APPLYING → PROCESSING → REFUNDED`，外部（含后台列表）无法观察到中间态。契约未对中间态的可观测性表态，因此本次按现状保留，未做拆分。
- **`TRAVELLING` 状态不可申请退款。** 契约未列明该状态下是否允许退款，当前实现拒绝。这属于需要产品口径确认的开放项，暂不修改。

上述四项中，前两项是集成深度问题，后两项是需要团队拍板的业务口径问题；均不影响本轮订单/出行人/退款参数的契约对齐修复。
